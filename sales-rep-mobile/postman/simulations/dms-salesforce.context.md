# DMS Salesforce simulation

## Purpose
Local HTTP stand-in owned by this repository, derived from `DmsPortalApi`, the invoice contract and `config/dms-returns.openapi.json`. It exercises the real Express routes and `DmsTransport`; Salesforce business rules are tested separately with Apex.

## Execution
From `sales-rep-mobile`, run `postman simulation run postman/simulations/dms-salesforce.sim.yaml --port 4916 --output ndjson` in a background process, logging outside version control. Wait for the `listening` event. In `backend`, set `DMS_SIMULATION_URL=http://localhost:4916/salesforce` and run `npm test`. Inspect request events; stop only that simulation's recorded process tree afterwards.

For the sign-in email path, use the same `DMS_SIMULATION_URL` and run `npm test -- src/dms/loginEmail.simulation.test.ts src/dms/router.test.ts` from `backend`. This test exercises the retained Salesforce sender adapter; the live DMS login now uses the configured Gmail SMTP sender. SMTP transport is tested separately, with credentials outside the repository. The simulation mailbox contains synthetic test codes only and is never part of the production API.

## Assumptions
- The mock is a narrow contract fixture, not a replacement implementation of approval, stock or Salesforce permissions. Actual primary work-item assignment, secondary manual decisions, foreign ownership, remaining quantity and idempotency passed isolated org tests on 2026-10-27 (`DmsDistributorReturnsTest` and existing workflow suites).
- Test requests use synthetic identifiers and the mock session header; no production credentials or business records are sent to the simulation. Observed 2026-10-27 in the transport suite.
