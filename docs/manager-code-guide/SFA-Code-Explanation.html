Current PJP flow

  1. Salesforce User maps to an active Employee.
  2. The LWC loads that Employee’s assigned active Beats and plans.
  3. A draft stores the PJP header and selected Beat junction records.
  4. Submit changes custom status to Submitted and identifies the configured manager.
  5. The authorized manager approves or rejects; the server records audit details.
  6. The approval trigger invokes allocation synchronization.
  7. For active outlets under selected Beats, the service inserts missing Employee–Outlet pairs or reactivates existing allocations.

Core concepts in simple words

Apex

Salesforce server-side code. Controllers expose entry points; services keep reusable business logic; triggers react to record changes.

LWC

Lightning Web Component: HTML defines the template, JavaScript manages state and calls, CSS styles the UI, and XML defines where Salesforce can expose it. These components are not the APK source.

SOQL and DML

SOQL SELECT queries read Salesforce records. DML insert/update/delete/upsert changes them. A query is not a save, and upsert is not automatically a complete duplicate-prevention strategy.

Id and __c / __r

Id is a Salesforce record identifier. __c normally identifies a custom object or field; __r traverses a custom relationship. Legacy API names can remain even when business labels change.

List, Set and Map

List keeps an ordered collection; Set keeps unique values; Map looks up a value by key. Here they support collecting IDs, preventing duplicate selections and joining records without per-record queries.

DTO / wrapper

A small class that carries data between Apex and JavaScript. It shapes the response without requiring the UI to interpret raw database records.

@AuraEnabled and cacheable

@AuraEnabled exposes an eligible Apex method to Lightning. cacheable=true is for read-only methods and allows client caching; imperative calls are explicit JavaScript calls, not continuous live synchronization.

with sharing / without sharing

with sharing concerns record-level sharing. It does not by itself enforce object permissions or field-level security. without sharing is especially sensitive and needs a deliberately constrained calling path.

SYSTEM_MODE

An explicit database access mode. Do not describe this as automatic user-level CRUD/FLS enforcement. Identity checks and operation-specific authorization still matter.

Bulkification

Collect IDs first, query a set of records, build maps, then perform list-based DML. This avoids putting one SOQL query or DML operation inside every iteration.

Transaction / rollback

A transaction groups related database work. An unhandled error can fail the transaction; a savepoint provides an explicit rollback target. In DmsTransactionApi, the REST execute wrapper owns that savepoint.

FOR UPDATE / idempotency

FOR UPDATE locks selected rows during the transaction. Idempotency means a retry should not create an extra business result. Neither is a substitute for every required database uniqueness rule.

Trigger.new / Trigger.oldMap

Trigger context supplies new records and/or previous versions, depending on the event. Comparing old and new values helps run logic only for meaningful changes.

@IsTest / runAs / startTest

Tests create isolated scenarios and assert outcomes. runAs changes the test user context; startTest/stopTest delimit tested work and asynchronous execution. Test source alone is not evidence of a passing run.

Promise / async / await

JavaScript waits for asynchronous server responses without blocking the page. try/catch handles failures; finally restores state such as loading indicators.

Reactive UI / recordId

Changing component state drives rendering. Salesforce supplies recordId to record components or actions; a setter can respond when that context arrives after construction.

25 likely manager questions — with answers

1. Explain the architecture in one minute.
The Salesforce UI uses LWC components. Their JavaScript calls Apex methods, Apex validates business rules and reads or writes custom objects, and triggers run when records change. Service classes hold reusable bulk logic. Tests create isolated fixtures and assert expected outcomes. The standalone mobile app/backend are separate layers; the three LWCs here are Salesforce UI components, not the Android APK screens.
2. Which controller does the current PJP screen use?
pjpMonthlyPlanner.js imports SfaPhaseOnePjpController. PjpPlannerController is a separate older daily/month controller still present in the folder. The current flow stores a date range and selected Beat child records and uses Submitted status; the older flow stores daily records and uses Pending.
3. Explain the entire PJP-to-outlet flow.
The logged-in User maps to an active Employee. Only active assigned Beats are offered. Saving creates/updates a Draft parent and replaces its PJP_Selected_Beat children. Submission records audit fields and notifies the manager. The configured manager can approve/reject. PjpApproverTrigger then calls SfaPjpAllocationService, which finds active outlets under those Beats and inserts/reactivates Employee Outlet Allocations.
4. Is PJP approval a standard Salesforce approval process?
Not in these PJP controllers: they implement state changes and authorization in Apex. DmsTransactionApi, separately, calls Approval.process for a native company-officer approval process. Do not confuse the two.
5. Why use a junction object for selected Beats?
One PJP can select several Beats and one Beat can appear in multiple PJPs. PJP_Selected_Beat stores one parent/Beat pair per row. Unique_Key combines their IDs. The parent Beat lookup remains for compatibility, while the junction holds the full selection.
6. Why are there Set, List and Map collections?
List preserves an ordered collection for response rows or bulk DML. Set removes duplicate IDs. Map gives direct key-based lookup, such as Employee/outlet pair to existing allocation, avoiding repeated searches and SOQL inside loops.
7. What does bulkified mean here?
Trigger services collect IDs from the whole batch, query related rows once per type and insert/update lists outside loops. The allocation test inserts 200 overlapping plans. Bulkification reduces query/DML calls, but does not remove all governor-limit or large-data-volume risks.
8. What does with sharing guarantee?
It addresses record-level sharing. It does not by itself prove complete object permission, field permission or business-identity checks. Those need suitable data access modes/checks and explicit authorization. Explain the actual filters instead of saying the code is automatically fully secure.
9. Why use system mode or without sharing?
Some trigger-maintained allocations and protected audit fields must be written consistently even when the initiating user cannot directly edit them. SfaPjpAllocationService is internal automation, while the current PJP controller checks employee and approver identities before privileged writes. These privileged paths should remain tightly controlled.
10. How are duplicate allocations prevented?
The service locks affected Employee rows, looks up existing Employee/outlet pairs and inserts only missing pairs. It uses a composite key in memory and prefers an existing Active record. This is idempotent for cooperating calls, not a universal uniqueness constraint across unrelated writers.
11. Why FOR UPDATE?
It locks queried rows until the transaction finishes so overlapping decisions or synchronization calls do not race as easily. PJP decisions lock the plan; allocation synchronization locks Employee rows. Locks can still contend, so callers must handle failures.
12. What is @AuraEnabled and cacheable=true?
AuraEnabled exposes eligible Apex methods/properties to Lightning clients. cacheable=true marks a read-only method that may be cached. Saving methods are not cacheable. These LWCs invoke Apex imperatively with async/await rather than @wire.
13. Why use a recordId setter in the outlet selector?
The quick-action record context may arrive after the component is created. The setter starts loading when a real Beat ID is supplied. A hasLoaded guard prevents duplicate startup loads, though it does not handle a later different record ID in the same instance.
14. Why validate both in JavaScript and Apex?
Client validation gives fast feedback, but users or other callers can bypass the UI. saveSelection independently enforces at most ten unique outlets and validates their geography/activity before saving.
15. Does Select Outlets only display outlets already in the Beat?
No. getSelectorData offers active outlets in the Beat's geography and preselects those currently assigned to the Beat. Saving can move an outlet from another Beat and remove deselected assignments. Employee allocation filtering is a different function.
16. Does saving a PJP automatically remove old allocations?
No. The allocation service creates or reactivates assignments. It does not revoke allocations on rejection, plan expiry or deletion, nor automatically resynchronize every future outlet/junction change.
17. Does uploading a profile picture update the avatar URL?
No. The LWC uses standard Salesforce File upload with the Employee record ID, displays the uploaded filename and closes. There is no code here to set Profile_Photo_URL__c or select the current avatar.
18. Does an invitation email contain a login code?
No. The employee service sends an application link and the chosen login email; the message says a code is requested later. Its link is still localhost. The legacy representative service uses a fixed older Expo build link and a custom app deep link.
19. Can you prove email delivery from these tests?
No. The tests inspect Limits.getEmailInvocations, which measures sendEmail API calls. They do not prove delivery to an inbox, correct mailbox routing or SMTP/deliverability configuration.
20. What actions does SfaVisitActionsController save?
Asset surveys, competitor activities, shop stock checks, support tickets and product returns, only when the queried Visit is Checked In. A separate method creates Pending leave requests for the logged-in Employee. It does not place sales orders or complete checkout.
21. What is the role of a test class?
Test classes arrange isolated data, invoke code and assert outcomes. TestSetup shares fixtures across methods. startTest/stopTest delimit the tested execution and its limit accounting; runAs changes the test user context. Source inspection alone cannot give a current pass result or coverage percentage.
22. Which important gaps should I mention honestly?
The older PJP decision method lacks an explicit approver identity check; the current form can submit a saved draft without persisting later edits; invitation URLs are hard-coded; file upload is not avatar synchronization; most visit-action validation is minimal; allocation removal/expiry is absent. These are findings, not fixes made during this explanation task.
23. Is the DMS transaction source definitely deployed and live?
No. The prior schema-only deployment did not deploy the DMS transaction class or routing trigger. Explain them as local integration source pending separate deployment/testing, not as proof of a working mobile flow.
24. What does the DMS endpoint do if a transaction fails?
execute sets a savepoint and catches failures, rolling back header/line changes made after it. It returns HTTP 400 with an expected validation message or a generic unexpected-error message. The rollback wrapper is not automatically used by direct calls to its helper methods.
25. What do the XML, HTML, JavaScript and CSS files each do?
HTML defines the UI structure and bindings. JavaScript holds state, event handlers and Apex calls. CSS controls layout/appearance. js-meta.xml controls Salesforce exposure/placement. Apex cls-meta.xml sets platform API version/status; it is not the class implementation.
